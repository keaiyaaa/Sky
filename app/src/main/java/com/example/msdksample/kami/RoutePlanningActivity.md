# 航线规划页面

## 作用与入口

首页“规划航线”打开 `com.example.msdksample.kami.RoutePlanningActivity`。页面负责 F07 本地航线编辑、F08 本地最近邻优化、F09 示例区域校验和 F11 本地模拟巡检。航线及执行记录写入 `route_planning.db`，没有自动填充的示例任务。

## 最小接入示例

```kotlin
startActivity(Intent(this, RoutePlanningActivity::class.java))
```

页面无必填 Intent 参数、props 或公开页面方法，无 Activity 返回结果或 emits。当前选择的航线标识仅作为偏好保存；实际业务内容始终从 SQLite 查询。

## 使用方式

1. 从首页进入，首次使用时自动创建一条空航线。
2. 在地图上加点，或点击“坐标添加”输入 WGS84 经纬度和相对高度。
3. 点击列表中的航点修改坐标、高度或删除。地图拖拽松手后提交一次保存。
4. 点击“编辑航线”维护名称、任务名称、巡检时间和优先级；删除需二次确认。
5. 点击“本地优化”查看前后相邻航段距离，确认后保存。下一次编辑或切换前可以撤销本次优化。
6. 点击“开始本地模拟”，选择正常、上传失败或执行中断连场景，确认后执行。执行期间可暂停、继续或取消。
7. 点击“执行记录”查看状态、进度、任务标识和事件时间线。记录超过 50 条后可翻页。

## 状态和约束

- 航线最多 3 条，每条最多 99 点。经纬度必须有限且处于合法范围，高度范围为 0 至 500 米。
- 添加、坐标修改、拖拽、保存、优化和执行前共用业务层校验。禁飞规则检查点和相邻航段，重叠参考区不能覆盖禁飞规则。示例限高为 60 米，跨越限高区的航段使用较高端点高度保守判断。
- 数据库操作在 IO 线程执行。先提交事务再重新查询并刷新页面，失败时保留已保存内容。
- 活动任务在数据库中锁定原航线，绕过页面也不能修改或删除；终态后解锁。
- 地图失败时保留列表、坐标编辑、优化、执行和历史查询；“重试底图”恢复网络加载。
- 本地模拟使用应用级执行器，离开页面后同进程继续执行。进程被系统终止后，下次进入会将遗留任务标记为中断，不会自动重新执行。
- “生成航线文件”只复用已有导出器，不等于上传成功。F10 的航点动作及设备接受性由相应负责人联调。
- 真机入口明确阻止执行，待 F02/F03、正式区域数据、F10/F12 和设备验收完成后再开放。

## 对外联动

页面通过 `RouteMapCallbacks` 接收地图事件；通过 `LocalMissionRuntime.state` 订阅已持久化的执行结果。任务启动只传航线稳定标识，执行器重新读取数据库快照，不信任页面传入的未保存列表。飞行日志已通过 `MissionRunRepository.logs()` 查询同一份正式事件。任务中心还可通过 `history()`、`get()`、`waypoints()`、`events()` 接入来源明确的记录，无需复制演示数据。
